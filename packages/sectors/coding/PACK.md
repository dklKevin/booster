# coding sector package

Use this pack for developer tools, infrastructure platforms, coding agents, IDEs, and technical product marketing aimed at software teams.
Load with the form package matching the page's job, plus 2-3 refs total chosen for the brief.
Refs teach how to think, never what to build.

## The coding mode (avoid)

- Avoid the near-black developer canvas - GitHub uses #000, Linear #08090a, and GitLab #171321 - punctuated by purple, blue, or pink radial glows.
- Avoid a huge centered future-of-building, AI, agent, or DevSecOps promise followed by dual signup/deploy and sales/learn CTAs.
- Avoid making a glowing IDE, terminal, issue tracker, or dashboard facsimile the automatic hero proof object, especially inside glass panels with hairline borders.
- Avoid the long procession of 12-column split showcases, rounded feature grids, sticky product cards, carousels, and numbered workflow chapters.
- Avoid treating enterprise-logo marquees as an opening proof ritual, then following them with a named testimonial and oversized ROI or scale metrics.
- Avoid the default typography shorthand of a variable sans for every marketing surface plus a monospace face for commands, labels, navigation, or technical seasoning.
- Avoid repeating the same high-commitment/lower-commitment CTA pair in the hero and closing banner before a dense five- or six-column taxonomy footer.
- Avoid abstract glow, particle, and gradient decoration when the only imagery is polished product UI and customer marks rather than a product-specific visual idea.

## Tells

- A near-black hero, tightly tracked platform claim, paired CTAs, and a luminous software mockup signal the sector default immediately.
- A logo marquee followed by a customer quote, a scale statistic, and an analyst link reads as formulaic developer trust staging.
- Layered charcoal cards, one-pixel translucent borders, monospace micro-labels, and purple-blue action color form the standard coding-site costume.
- Alternating product screenshots in a 12-column shell that terminate in a directory-like footer make the page interchangeable with its peers.

## Register

- Credibility is load-bearing when proof is inspectable: install commands, runtime examples, benchmark bars, accurate editor or terminal states, and real product mechanics should sit close to the claim.
- Customer scale and quantified outcomes matter when named and contextualized, while logo abundance, generic millions-of-users claims, and unverified badges are decoration rather than proof.
- The audience expects concise technical language, legible code typography, compact interface detail, and clear distinctions between proposition, explanation, and implementation.
- Excellence can be warm, editorial, or playful without losing rigor: Fly.io and Railway use serif-led infrastructure narratives, while Val Town connects friendly world-building to a concrete terminal.
- A product metaphor earns trust only when it governs behavior and structure, as in PostHog's application frame, Railway's deployment journey, Zed's ruled editor scaffold, or Raycast's accurate command windows.
- Restraint signals confidence: quiet semantic surface ladders, one purposeful accent family, readable prose measures, and reduced-motion handling outperform indiscriminate glow, color, and animation.
